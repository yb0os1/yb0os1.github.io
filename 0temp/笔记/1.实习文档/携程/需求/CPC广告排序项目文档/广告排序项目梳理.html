Rank Platform 项目梳理文档

一、项目概述

1.1 项目简介

Rank Platform 是携程旅游（Ctrip）的AI排名平台，用于对旅游产品（如邮轮、广告等）进行智能排序。项目采用Java 21开发，基于Spring Boot框架，使用工作流编排（Flow Orchestrator）实现复杂的排序流程。

1.2 技术栈

  • 语言: Java 21
  • 构建工具: Maven
  • 框架: Spring Boot
  • 工作流引擎: Flow Orchestrator (自定义)
  • 测试框架: Spock (Groovy), JUnit
  • 缓存: Redis (Jedis, Credis)
  • RPC框架: Baiji RPC
  • 日志: Logback, TripLog
  • 监控: CAT (携程监控系统)

1.3 项目结构

二、核心功能

2.1 业务功能

项目主要支持两类业务：

2.1.1 产品排序（Product Ranking）

  • 邮轮产品排序 (cruiseProductRanking)
    • 套餐包打散算法
    • 新品插空算法
    • 白盒排序（规则排序）
    • 黑盒排序（模型排序）
    • 人工干预排序

2.1.2 广告排序（Ad Ranking）

  • 广告排序 (adRanking)
    • 特征维度组装
    • 融合评分计算
    • 白盒/黑盒排序
    • 人工干预

2.2 核心算法

2.2.1 套餐包打散算法

位置: PackageDispersionUtils.java

算法思路: 基于LeetCode 621. Task Scheduler的思路实现

  • 阶段1: 构建基础列表（框架）- 包含锚点和无同线路产品
  • 阶段2: 在基础列表的间隙中计算填充位置
  • 阶段3: 在基础列表的间隙中插入打散产品

核心规则:

  • 锚点（每条线路最高分产品）位置固定
  • 同线路产品之间至少间隔 minGap 个位置
  • 框架位置完全固定，不会因为填充而推后

文档: docs/套餐包打散算法设计文档.md

2.2.2 邮轮新品插空算法

位置: NewProductSlottingUtils.java

算法思路: 贪心算法 + 双指针合并

  • 阶段1: 数据准备（分离新品和非新品）
  • 阶段2: 新品按精排分排序（贪心策略）
  • 阶段3: 生成插空位置序列 [2, 4, 8, 12, 16, 20, …]
  • 阶段4: 位置决策（选择更优位置：min(原rank, 目标插空rank)）
  • 阶段5: 冲突处理
  • 阶段6: 双指针合并（维护非新品相对顺序）
  • 阶段7: 重新设置rank

文档: docs/邮轮新品插空算法.md

三、架构设计

3.1 分层架构

3.2 工作流编排

项目使用 Flow Orchestrator 进行工作流编排，通过DAG（有向无环图）定义排序流程。

工作流定义:

  • adRanking: 广告排序工作流
  • cruiseProductRanking: 邮轮产品排序工作流

节点类型:

  • 数据处理节点: IngestData, CreateProductInfo
  • 特征处理节点: AssembleFeatureDimensions, CalculateDimensions
  • 排序节点: WhiteBoxRank, BlackBoxRank, ReRank
  • 业务节点: CruiseGroupDispersion, CruiseNewProductSlotting
  • 验证节点: ValidateProduct
  • 结果处理节点: SetRank, SortProductList, CreateRankResult

3.3 核心组件

3.3.1 路由组件

RankServiceRouter:

  • 根据 bizId 路由到对应的业务服务
  • 使用 @BizAnnotation 注解标识业务服务
  • 支持产品排序和广告排序两种路由

3.3.2 业务服务

ProductRankService:

  • DefaultProductRankService: 默认产品排序服务实现
  • 支持邮轮产品排序

AdRankService:

  • DefaultAdRankService: 默认广告排序服务实现

3.3.3 处理器（Processor）

  • AdContextProcessor: 广告上下文处理
  • CruiseContextProcessor: 邮轮上下文处理
  • ProductFeatureDataIngestionProcessor: 特征数据注入
  • ProductBlackBoxRankProcessor: 黑盒排序处理
  • ProductRecordContextProcessor: 上下文记录

3.3.4 节点（Node）

邮轮节点 (node/cruise/):

  • CruiseIngestData: 数据注入
  • CruiseCreateBaseProductInfo: 创建基础产品信息
  • CruiseAssembleFeatureDimension: 组装特征维度
  • CruiseGroupBuilding: 套餐包分组
  • CruiseGroupDispersion: 套餐包打散
  • CruiseNewProductSlotting: 新品插空
  • CruiseWhiteBoxRank: 白盒排序
  • CruiseBlackBoxRank: 黑盒排序
  • CruiseReRank: 重排序
  • CruiseSetRank: 设置排名
  • CruiseSortBaseProductList: 排序产品列表
  • CruiseValidateProduct: 验证产品
  • CruiseManualRank: 人工干预排序

广告节点 (node/ad/):

  • IngestData: 数据注入
  • CreateProductInfo: 创建产品信息
  • AssembleFeatureDimensions: 组装特征维度
  • CalculateDimensionsAndSupplement: 计算维度并补充
  • FusionScoringCalculator: 融合评分计算
  • WhiteBoxRank: 白盒排序
  • BlackBoxRank: 黑盒排序
  • ReRank: 重排序
  • SetRank: 设置排名
  • SortProductList: 排序产品列表
  • ValidateProduct: 验证产品
  • ManualRank: 人工干预排序

十三、关键特性

13.1 业务特性

  1. 多业务线支持: 通过 @BizAnnotation 和路由机制支持多个业务线
  2. 工作流编排: 使用DAG定义复杂的排序流程
  3. 算法丰富: 包含打散、插空、白盒、黑盒等多种排序算法
  4. 人工干预: 支持人工干预排序结果
  5. 特征工程: 完整的特征组装和计算流程

13.2 技术特性

  1. 高并发: 使用线程池管理并发处理
  2. 缓存优化: 大量使用Redis缓存提升性能
  3. 可扩展: 通过节点机制灵活扩展功能
  4. 可测试: 完善的单元测试覆盖
  5. 可监控: 集成CAT监控和日志系统

十四、项目亮点

  1. 算法创新:

    • 套餐包打散算法基于LeetCode Task Scheduler思路，性能优化后提升50-70%
    • 新品插空算法使用贪心+双指针，保证非新品相对顺序

  2. 架构设计:

    • 工作流编排实现复杂业务逻辑的可视化和可配置化
    • 路由机制支持多业务线统一入口

  3. 性能优化:

    • 算法复杂度优化（O(n×m) → O(n+m)）
    • 缓存策略优化
    • 线程池管理优化
