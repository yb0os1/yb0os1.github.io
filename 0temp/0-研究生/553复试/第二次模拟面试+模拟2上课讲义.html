为什么 function(str1, str2) 调用第二个 function？

当你调用 function(str1, str2) 时，str1 和 str2 都是字符数组（char[]），而在 C++ 中，数组名会自动转换为指向数组首元素的指针。也就是说：

  • str1 被转换为 char *（指向字符数组的指针）。
  • str2 被转换为 char *（指向字符数组的指针）。

因为 str1 和 str2 被转换为 char *，它们的类型是 char *。但是，我们有两个 function 重载版本，一个接受 const char *（常量字符指针），另一个接受 char *&（可修改的字符指针引用）。

在这种情况下，由于 str1 和 str2 是数组名，它们的类型实际上是 char *，而不是 const char *。因此，编译器会选择接受 const char * 类型参数的第二个版本的 function，因为：

  1. str1 和 str2 都是可修改的字符数组，但它们被隐式转换成 char *。
  2. 第二个 function 使用的是 const char *，它可以接受 char * 类型的参数，而不会因为不能修改原数组而产生冲突。

当你传递 str1 和 str2（char[]）到 function(str1, str2) 时，str1 和 str2 会被转换成 char * 类型（指向字符数组的指针）。
由于第二个 function 版本使用 const char *，它能够匹配 char * 类型的指针，因此会调用第二个版本的 function。
第一个 function 版本要求可修改的字符指针引用，这与 const char * 不兼容，因此不会被调用。

6. 函数重载与重写

  • 函数重载：func 有三个重载版本（参数为 Base&、Base*、Base）。
  • 函数重写：Derived 的 print() 重写基类虚函数。

7. 动态内存管理

  • 正确释放内存

    二维数组需手动释放（delete[] arr[i]; 和 delete[] arr;）。

    • 基类析构为虚，确保 delete b 正确释放派生类资源。

易错点总结

  1. 对象切片：传递派生类对象给 func(Base b) 会导致多态失效。
  2. 静态函数调用：b.staticPrint() 调用基类版本（静态函数不支持多态）。
  3. 虚函数必要性：若基类析构非虚，delete b 会导致内存泄漏。

5、

Processor 类

  • operator() 是纯虚函数，派生类必须实现。
  • 虚析构函数确保正确释放派生类对象的资源。

Multiplier 类

  • 继承自 Processor 类，实现了 operator() 函数。
  • 当 val > 0 时，将 val 乘以 factor，并增加 mulCount。
  • 提供静态成员函数 getMulCount() 用于获取 mulCount 的值。

Accumulator 类

  • 继承自 Processor 类，实现了 operator() 函数。
  • 当 val 为偶数时，将 val 累加到 sum 中，并增加 addCount。
  • 提供静态成员函数 getAddCount() 用于获取 addCount 的值，以及普通成员函数 getSum() 用于获取 sum 的值。

Hybrid 类

  • 继承自 Multiplier 和 Accumulator 类，实现了 operator() 函数。
  • 先调用 Multiplier 类的 operator() 函数，再调用 Accumulator 类的 operator() 函数，最后增加 counter。
  • 提供普通成员函数 getCounter() 用于获取 counter 的值。

process 函数：接受一个 Processor 类的引用和一个整数数组，对数组中的每个元素调用 p(arr[i]) 进行处理，并输出处理结果。

p2 是一个 Processor 类型的引用，它绑定到 Accumulator 类的实例（通过 Hybrid 对象 h 转型）。然而，尽管 p2 类型是 Processor&，它实际指向的是 Hybrid 类的对象，并且 Hybrid 类重载了 operator() 运算

虽然 p2 被声明为 Processor& 类型，但它绑定到一个 Hybrid 对象 h（h 的类型是 Hybrid，但通过 Accumulator 引用使用）。
