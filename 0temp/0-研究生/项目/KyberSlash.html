KyberSlash: Exploiting secret-dependent division timings in Kyber implementations

利用Kyber实现中的依赖秘密的除法时序漏洞

Kyber 是 NIST 标准化的后量子 KEM（ML-KEM） 后续可以具体学习一些这些后量子密码

常数时间实现是对抗时间侧信道攻击的关键，但编译器/处理器可能在无意中引入变时序指令（比如除法、某些乘法在嵌入式上也可能是可变时钟），破坏常数时间假设。

论文中展示了两代KyberSlash

共同根源：源码中有针对常数时间写法的除法表达（对常数 3329 的除法 /KYBER_Q），在某些编译器/优化选项或平台上并没有被优化成常数时间的乘法，而是保留/生成了可变时序的除法（或软件调用 div 子例程），这造成时序依赖输入值，从而泄露秘密相关信息。

为什么除法会变成“变时序指令”

在 C 里写 x / 3329，许多编译器会把“除以常数”优化成乘法+移位（即常数时间）。但是某些 编译器版本 或 优化选项（例如 gcc -Os 或 某些交叉编译器/架构）会 不做 这个转换，而是生成：

  • 一个真正的硬件除法指令（如 x86 的 idiv），或
  • 一个对除法做封装的软件子例程（如 divsi3），这个子例程对不同的被除数耗时不同（soft-division）

这些硬件或软件除法在不同输入下耗时会出现“跳变”——例如当被除数跨过某些阈值（如等于或超过除数、达到 4096、8192 等）时，子例程会多做步骤或进入不同分支，从而多耗若干个 CPU 周期。作者在平台上测得这些跳变足够大，可以在噪声中被区分。

KyberSlash1 的直观做法

解密时的某个中间系数 m'[i] = v' - ⟨u', s⟩（这是解密得到的多项式系数）。这个 m'[i] 进入上面的除法表达式，除法的被除数就是 2*m'[i] + KYBER_Q/2（或等价表达），因此除法的·耗时会取决于 m'[i] 的数值范围。

攻击者构造特定的密文（选择 u 和 v），使得对目标系数 m'[i] 的值成为一个关于 secret s 的线性表达（例如 m'[i] = 208 - 72 * s_coeff 之类）。因为 secret coefficients（Kyber 的 s 的系数）只在一个小范围（例如 -3…3），根据不同的 s 值，m'[i] 会落在不同的区间（比如小区间导致“快速除法”，另一区间导致“慢速除法”）。

那么：发送这个特制密文多次，并精确测量整个 decapsulation 的耗时（也可以把噪声通过大量测量平滑掉），如果观察到“慢”或“快”的两类时间，就能判断出 s_coeff 的某个值或把可能值集合缩小。重复对不同位索引实施，就能逐系数恢复秘密。作者在 Raspberry Pi（Cortex-A7）上实测能在几小时内恢复 Kyber512 的密钥
