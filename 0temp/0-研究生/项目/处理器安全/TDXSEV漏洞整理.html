威胁模型

攻击者能力

  • 系统层面控制：攻击者可能拥有对系统管理程序（Hypervisor）的部分或全部控制权，能够调整系统配置，如 CPU 频率、中断设置等
  • 微架构利用：熟悉 CPU 微架构，包括缓存、分支预测等机制，利用这些微架构特性实施侧信道攻击
  • 代码注入与滥用：通过软件漏洞或合法 API 的滥用，向 TEE 环境中注入恶意代码或干扰正常执行流程

攻击目标

  • 数据窃取：获取 TEE 中存储的敏感数据，如加密密钥、用户隐私信息等
  • 控制流篡改：改变 TEE 内程序的执行流程，实现恶意操作，如执行未经授权的代码

攻击方法

  1. 单步执行攻击（Single-Stepping）
  • 攻击对象：TDX、SEV
  • 核心方法
    • TDX：通过降低 CPU 频率绕过时间差检测（CVE-2024-27457），结合 TLB 刷新延长首条指令执行时间，实现逐指令控制
    • SEV：利用#VC中断触发单步模式（SEV-Step 攻击），结合页错误控制通道
  • 缺陷原因
    • 时间差检测依赖 rdtsc 计数器（与物理频率无关），易被频率操控绕过
    • 中断处理逻辑未完全隔离 TEE 执行
  • 攻击效果
    • 窃取加密密钥（如 ECDSA 非 ce 泄漏）、控制流信息
    • 影响：WolfSSL 的 CVE-2024-1544，OpenSSL 的非 ce 生成漏洞
  1. 缓存侧信道攻击（Cache Side-Channel）
  • 攻击对象：TDX、SEV
  • 核心方法
    • TDX：StumbleStepping 攻击利用预防模式中 TDVPS 页面的访问次数推断指令数
    • SEV：通过Flush+Reload监测加密内存访问模式（如 CIPHERLEAKS 攻击）
  • 缺陷原因
    • 内存加密（MKTME/SEV-ES）未完全隔离缓存标签，不同 KeyID 访问导致缓存冲突
    • 预防模式的重复访问形成可观测的侧信道信号
  • 攻击效果
    • 泄露指令计数、控制流分支（如 wolfSSL 的 ECDSA 15 位 MSB 泄漏）
  1. 加密算法实现漏洞
  • 攻击对象：TEE 内的加密库（如 wolfSSL、OpenSSL）
  • 核心方法
    • 利用非 ce 生成的截断法漏洞（如 wolfSSL 的_sp_div_impl循环次数泄漏）
    • 结合单步攻击或 StumbleStepping 获取控制流信息
  • 缺陷原因
    • 非 ce 生成未采用恒定时间算法，导致循环次数依赖高位比特
  • 攻击效果
    • 恢复 ECDSA 私钥（如 wolfSSL secp160r1 的 15 位泄漏）
    • 相关 CVE：CVE-2024-1544（wolfSSL）、OpenSSL 的非 ce 泄漏（未分配 CVE）
  1. 故障注入攻击
  • 攻击对象：SEV、TDX
  • 核心方法
    • SEV：CacheWarp 攻击通过选择性状态重置绕过完整性保护
    • TDX：利用wrmsr指令干扰 APIC 定时器，触发异常中断
  • 缺陷原因：硬件状态恢复机制存在漏洞，允许部分状态保留
  • 攻击效果：破坏 TEE 的完整性验证，执行任意代码

威胁模型

攻击者具备多种能力以实施对 TEE 的攻击：

  • 系统层面控制：攻击者可对系统管理程序（Hypervisor）进行部分或全部控制，能够调整系统配置，如 CPU 频率、中断设置等。
  • 微架构利用：熟悉 CPU 微架构，包括缓存、分支预测等机制，利用这些微架构特性实施侧信道攻击。
  • 代码注入与滥用：通过软件漏洞或合法 API 的滥用，向 TEE 环境中注入恶意代码或干扰正常执行流程。

攻击目标主要有两个方面：

  • 数据窃取：获取 TEE 中存储的敏感数据，如加密密钥、用户隐私信息等。
  • 控制流篡改：改变 TEE 内程序的执行流程，实现恶意操作，如执行未经授权的代码。

攻击特点比较

  • 单步执行攻击：通过操控系统层面（如 CPU 频率、中断）来实现对 TEE 指令执行的逐指令控制，主要针对 TDX 和 SEV 的底层执行机制，利用时间差检测和中断处理逻辑的缺陷。
  • 缓存侧信道攻击：利用 CPU 缓存机制的漏洞，通过监测内存访问模式或页面访问次数来获取指令计数、控制流分支等信息，对 TDX 和 SEV 均有效，主要是由于内存加密未完全隔离缓存标签导致。
  • 加密算法实现漏洞攻击：针对 TEE 内加密库的算法实现缺陷，利用非恒定时间算法导致的循环次数依赖问题，恢复 ECDSA 私钥，主要影响 TEE 内的加密操作。
  • 故障注入攻击：通过干扰硬件状态（如定时器、缓存状态）来触发异常中断或绕过完整性保护，破坏 TEE 的完整性验证，对 TDX 和 SEV 都有威胁，根源在于硬件状态恢复机制的漏洞。

未来攻击点思考

  • 系统层面控制的深度利用：进一步探索如何更隐蔽地控制系统管理程序，如发现新的系统配置调整方法，以绕过更复杂的安全检测机制。
  • 微架构漏洞挖掘：随着 CPU 微架构的不断发展，持续研究缓存、分支预测等机制的新特性，寻找新的侧信道攻击点。
  • 加密算法的安全评估：对 TEE 内使用的各种加密算法进行全面的安全评估，发现新的算法实现漏洞，特别是针对新兴加密算法的研究。
  • 硬件状态恢复机制的攻击：深入研究硬件状态恢复机制的细节，找到更多可利用的漏洞，提高故障注入攻击的成功率。
