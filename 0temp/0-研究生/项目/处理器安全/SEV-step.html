了解师兄论文中在不同进程中打破隔离的方式：

  • 利用隐藏计数器打破进程隔离：发现 AMD 处理器中存在未公开的隐藏计数器，其状态在上下文切换时不会被刷新。实验：当父子进程绑定到同一个核心时，子进程能读取父进程留在处理器核心中的计数器状态 。这打破了不同进程间原本应有的地址空间隔离，使得不同进程可以共享计数器状态。利用这一特性，通过设计基于驱逐现象的计数器复用机制，构造了跨进程隐蔽信道。木马进程与间谍进程可将自己绑定到约定核心上，木马进程训练计数器状态，间谍进程探测计数器状态，从而实现进程间信息的隐蔽传输，在不同进程间建立了非法通信渠道
  • 利用推测性存储绕过预测器打破进程隔离：推测性存储绕过预测器由指令物理地址索引，利用操作系统的写时复制机制，在父子进程通过 fork () 系统调用创建时，父子进程对特定函数（如 stld 函数）的调用具有相同物理地址，它们对该函数的调用将访问索引值相同的计数器 。这使得不同进程可以通过操作相同的计数器，实现跨用户进程隐蔽信道。木马进程与间谍进程虽无法约定索引值访问相同推测性存储绕过预测器表项，但可使用类似滚动数组的方式尝试碰撞，检测碰撞发生来传输信息，打破了不同用户进程间的隔离

上面的思想同样可以用于在安全虚拟机和 hypervisor 中打破隔离的基本思想

  • 基于推测性存储绕过预测器打破安全虚拟机和 hypervisor 的隔离：推测性存储绕过预测器状态在上下文切换时不被刷新，这一性质不仅存在于用户进程间，在更广泛的场景中同样存在。在跨 SEV - SNP hypervisor 与安全虚拟机的场景中，通过部署 AMD 官方提供的 SEV hypervisor 及安全虚拟机环境，利用 qemu - affinity 工具将 qemu 创建的虚拟机进程绑定到宿主机的指定核心上，并在两者间开辟共享内存用于信号量的创建与使用 。推测性存储绕过预测器的状态可以在 hypervisor 与安全虚拟机间复杂的切换过程中维持不变，从而实现了跨 SEV - SNP 隐蔽信道，打破了安全虚拟机和 hypervisor 之间的隔离，使得攻击者可以在两者之间传输信息，威胁到了安全虚拟机的安全性

SEV-Step: A Single-Stepping Framework for AMD-SEV

关注AMD 安全加密虚拟化（SEV），提出了 SEV-Step单步执行框架，深入探讨了 SEV 在微架构侧信道攻击下的安全性问题

sev现状：AMD SEV 是一种保护整个虚拟机的 TEE，基于 AMD SVM 硬件加速虚拟化技术。它通过加密 VM 内存内容来抵御恶意的管理程序和部分物理攻击者。但是，自 SEV 发布以来，已遭受多种攻击 ，如利用未加密的 VMCB、嵌套页表、加密模式等方面的漏洞。在攻击技术方面，针对 Intel SGX 的单步执行攻击取得了显著进展，SGX-Step 框架实现了可靠的单步执行并提供了可复用的攻击框架，但 SEV 在这方面的研究相对滞后，此前的工作大多未发布可复用的成果或仅针对特定攻击，缺乏可靠的单步执行和通用的攻击框架。

SEV-step工具具体可以实现的功能：

  1. 页错误跟踪功能

    • 强制产生页错误：sev-step利用管理程序对嵌套页表的控制，通过修改页的相关位（如 present、no - execute 和 read/write 位），强制 VM 产生页错误并揭示访问类型
    • 快速定位代码区域：页错误跟踪粒度较粗但速度快，可用于在单步执行前快速定位感兴趣的代码区域。当 VM 即将执行包含依赖秘密的内存查找的代码页时，再启动单步执行进行更精确的攻击
  • 具体：借助管理程序对嵌套页表的控制来实现，能强制虚拟机（VM）产生页错误，进而揭示其内存访问类型
    • sev-step利用管理程序对嵌套页表的控制能力，通过修改页的一些关键相关位，像present（存在位）、no - execute（不可执行位）以及read/write（读写位）等，来强制 VM 产生页错误。例如，当把某页的present位设置为 0 时，若 VM 尝试访问该页，就会触发页错误异常
    • 当 VM 因页表位修改而产生页错误时，就能够揭示出 VM 对该页的访问类型，比如是读访问、写访问还是执行访问。这有助于攻击者了解 VM 的内存访问模式，从而定位到可能包含敏感信息或者关键代码的内存区域
  1. 单步执行功能
    • 每次只执行程序中的一条指令，执行完一条指令后暂停，等待进一步的操作指示再执行下一条指令
    • 精确控制执行流：借助sev-step，能够以单步方式执行受 SEV 保护的虚拟机（VM）中的代码。通过配置 APIC 定时器中断，让硬件在指令边界处理中断，确保中断在 VM 执行的第一条指令结束前触发，同时使指令进入执行流水线，从而实现单步执行。这一功能使攻击者可以精准关联微架构观察与受害者执行状态，在攻击过程中能够细致地观察每一条指令执行时系统的状态变化
    • 提高单步执行可靠性：为保证单步执行的可靠性，sev-step采取了一系列措施。例如刷新 VM 的 TLB 条目、重置 “accessed” 位来增加单步执行窗口时间；通过固定内核线程 CPU 核心、稳定 CPU 频率、禁用硬件缓存预取器等方式确保执行速度稳定；防止虚拟定时器中断干扰单步执行，并利用 VM 的性能计数器事件确定 APIC 定时器超时值，准确判断单步、零步和多步情况
  2. 缓存攻击功能
    • 适配 SEV 环境的攻击方式：由于 SEV 环境的特性，传统的 Load + Reload 和 Flush + Reload 攻击不可行，sev-step采用 Prime + Probe 攻击。在用户空间确定驱逐集，在内核空间实现 Prime 和 Probe 步骤，以减少缓存噪声
    • 测量缓存状态：通过性能计数器和 rdpru 指令测量访问时间，推断缓存状态，从而获取目标 VM 的内存访问模式等信息，为进一步的攻击提供支持
  3. 用户空间 API 交互功能
    • 实现内核与用户空间通信：sev-step基于 AMD 的 SEV 参考管理程序，通过 ioctl 和共享内存实现内核空间与用户空间的通信。ioctl 用于低频操作，共享内存用于高频的页错误和单步事件通知
    • 支持用户空间开发攻击逻辑：当 VMEXIT 事件发生时，内核空间通过共享内存向用户空间发送事件，然后等待用户空间确认，期间 VM 处于暂停状态。这使得用户空间能通过 ioctl API 修改配置，确保在下一次 VMRUN 时生效，将复杂的攻击逻辑放在用户空间更丰富、不易出错的编程环境中开发
