TDXdown: Single-Stepping and Instruction Counting Attacks against Intel TDX

针对英特尔TDX的单步和指令计数攻击

文章工作

可信执行环境（TEE）能保护计算和数据，即使面对特权攻击者（如控制管理程序的一方）也能确保数据安全

对TEE威胁最大的是侧信道攻击，其中单步攻击最强大：作为一种强大的攻击技术，对 Intel SGX 和 AMD SEV 构成严重威胁，它能增强现有侧信道攻击效果，还可用于指令计数攻击，揭示 TEE 的控制流，进而利用加密库中的微小泄漏

Intel TDX（第二代的TEE）配置了专门应对单步攻击的方式（设计了内置防御机制，包括检测单步中断模式的启发式方法和激活的预防模式）

这篇文章就是提出两种新攻击方式：利用TDX检测启发式的弱点进行单步攻击绕过防御和StumbleStepping 攻击

  1. 利用其弱点使得TDX单步执行对策失败

利用这两种有效的攻击原语， 分析了ECDSA 签名算法中随机数截断导致的泄漏问题，揭示了 wolfSSL 和 OpenSSL 的安全漏洞

基础

TDX架构

  • 受保护的虚拟机称为 信任域(TD)
  • 虚拟机监控程序需要调用TDX模块的SEAMCALL API来 管理信任域
  • 只有TDX模块可以进入信任域
  • 从信任域退出时,控制权返回给TDX模块, 而不是虚拟机监控程序

TDX模块在不可信的虚拟机监控程序和信任域之间形成了一个可信层

TDX 模块位于新增的受保护内存范围，引入安全仲裁模式（SEAM），分为 VMX root 和 VMX non - root 子模式，TDX 模块运行在 SEAM VMX root 模式，TD 运行在 SEAM VMX non - root 模式

TD 的内存使用多密钥全内存加密（MKTME），根据 KeyID 使用不同加密密钥，KeyID 分为共享和私有，私有 KeyID 仅在 SEAM CPU 模式下可用

TDX 控制数据结构

TD 的相关数据结构由 TDX 模块管理，如信任域虚拟处理器状态（TDVPS）描述 TD 中每个虚拟 CPU 的状态

该数据结构的内存由 管理程序分配后传递给TDX模块，TDX模块用私有MKTME KeyID加密，管理程序只能通过TDX模块的API与之交互

针对 Intel TDX 的缓存攻击

TDX使用MKTME对TD的内存进行加密 用来影响侧信道攻击

但是MKTME KeyID 编码在物理地址位中，是缓存标签的一部分

理论上不同 KeyID 访问相同数据会导致不同缓存标签和数据解密，但缓存一致性机制会在加载新 KeyID 数据前清除使用不同 KeyID 的现有条目，这使得攻击者可利用 Flush + Reload 风格的缓存攻击，通过不同 KeyID 访问 TD 内存将其从缓存中逐出

指令计数攻击

指令计数攻击是基于单步的针对TEE 的侧信道攻击，推断精细的控制流信息

攻击者假设已知执行的二进制文件，结合粗粒度的页错误控制通道和单步攻击，以指令粒度重构受害者的控制流，甚至能检测等长代码分支在指令序列中不同点的内存访问差异

为防范攻击，安全关键代码应采用数据无关的恒定时间范式：执行路径或任何内存访问不得依赖于秘密数据

攻击者模型

采用默认 TEE 攻击者模型，攻击者具有系统 root 权限，可使用页错误控制通道、编程 APIC 定时器和控制处理器频率，但不假设具有物理访问权限，如恶意或受损的云服务提供商试图从客户 TD 中泄露数据。

TDX 单步执行防御措施

TDX 中断架构

在Intel SGX和AMD SEV上,单步攻击 利用了外部中断(如APIC定时器中断)中止TEE的执行并将控制权返回给攻击者控制的操作系统或虚拟机监控器

在 TDX 中，攻击者控制的管理程序无法直接进入TD，TD 退出时控制权也不立即返回管理程序，而是由 TDX 模块处理。TDX 模块运行在特殊 CPU 模式，为管理程序提供 SEAMCALLs 管理 TD

虽然恶意管理程序可设置 APIC 定时器中断 TD，但中断后由 TDX 模块检测中断模式是否为攻击，若判定为攻击，则通过单步预防模式继续执行 TD 若干周期后再将控制权交回管理程序

单步执行检测

TD 因中断退出时，TDX 模块通过分析 TD 指令指针（RIP）前进字节数和进入退出 TD 的时间来判断中断行为

  1. 若 RIP 前进超过最长 x86 指令字节数的两倍，说明至少执行了两条指令，不是单步执行
  2. TDX 模块记录进入和退出 TD 的 rdtsc 时间戳（读取处理器的时间戳计数器）tb和ta，如果时间差ta-tb达到一定阈值，则认为中断行为正常，否则激活单步预防模式（TDX1.5 版本中阈值为 4096个 rdtsc 增量）

预防模式

检测到潜在单步攻击时，TDX 模块先禁用所有中断，防止管理程序干扰

然后以单步方式让 TD 执行随机数量（PmSteps）的指令

每次进入 TD 时设置 Monitor Trap Flag(监视陷阱标志)，使 TD 执行一条指令后退出，

重复此过程直到执行完 PmSteps 条指令，最后将控制权交回管理程序，使管理程序无法知晓 TD 的精确执行进度

由于执行的指令数量是随机的，执行过程中又禁止了管理程序干扰，管理程序无法得知 TD 到底执行了哪些指令、执行的顺序以及执行进度，也就难以利用单步攻击获取 TD 内部的敏感信息或破坏 TD 的正常运行

绕过单步执行防御机制

利用时间戳计数器特性：利用rdtsc时间戳计数器的频率不受CPU频率缩放影响的特点，攻击者利用这一特性，降低运行 TD 的 CPU 核心频率，使得在实际执行时间较长的情况下，TDX 模块测量的时间差仍能满足正常中断条件（td>4096个rdtsc）

  • 使用 Linux cpufreq驱动设置目标核心为powersave模式，通过cpufreq-set -g powersave将频率固定为 800MHz
  • 验证频率：通过cpufreq-info命令确认当前核心频率

借助 APIC 定时器实现单步攻击：攻击者使用 APIC定时器来触发中断，以实现单步攻击。确保定时器中断在首条指令执行期间命中，攻击者通过刷新 TD 的 TLB（缓冲区）来延长首条指令的执行时间。同时，选择合适的定时器设置，防止出现多步执行的情况

StumbleStepping攻击

针对 Intel TDX 单步执行预防模式的攻击方法，核心就是利用该模式中存在的缓存侧信道信息泄露问题，通过监测特定页面的访问情况来推断目标信任域（TD）执行的指令数量，进而揭示 TD 的控制流信息

攻击者利用 TDX 单步执行预防模式中的固有缓存侧信道。在预防模式下，TDX 模块每次进入和退出 TD 时，都会访问 TD 的虚拟处理器状态（TDVPS）页面。攻击者通过监测这些页面的访问次数，就能推断出 TD 执行的指令数。这是因为每次 TDX 模块进入 TD 执行一条指令，就会对应一次对 TDVPS 页面的访问操作，攻击者利用这一特性，通过特定的缓存攻击技术来获取这些信息。

核心原理

TDX 单步预防机制缺陷

  • 预防模式通过随机执行 PmSteps 指令（1-32 条），使管理程序无法追踪 TD 的精确执行进度
  • 每次 TD 进入 / 退出时，TDX 模块必须访问 TDVPS（虚拟处理器状态）页面以保存 / 恢复寄存器状态。该访问行为形成固定模式的缓存侧信道

缓存侧信道利用

  • KeyID-based Flush+Reload
    • TD 内存使用 MKTME 加密，不同 KeyID 访问同一物理地址时，缓存条目需被刷新
    • 攻击者利用此特性，通过监测 TDVPS 页面的缓存未命中次数，推断 TD 执行的指令数
    • 攻击者使用与目标不同的 KeyID 先将目标数据从缓存中清除，之后再尝试重新加载（Reload）该数据，通过测量重新加载数据的时间，就能判断目标是否在这期间访问过该数据。因为若目标访问过，数据会被加载到缓存中，攻击者重新加载时时间会较短；若目标未访问，数据需要从内存中读取，加载时间就会较长

攻击的步骤：

  1. 触发预防模式
    • 利用 APIC 定时器发送高频中断（如每 1μs 一次），迫使 TDX 模块持续检测单步攻击；TDX 模块的检测逻辑基于时间差，高频中断会缩短两次中断的时间间隔，触发预防模式
  2. 定位 TDVPS 敏感区域：（页面分析）
    • TDVPS 包含虚拟 CPU 的寄存器状态（如 RIP、RSP），大小约 16KB
    • 通过离线分析发现，每次 TD 进入 / 退出时，TDX 模块必然访问特定缓存行（如struct vcpu_state.rip）
    • CPU 缓存一致性协议要求不同 KeyID 访问同一物理地址时清除旧条目
  3. 缓存侧信道构建
    • KeyID-based Flush+Reload 流程：
      • Flush：攻击者用不同 KeyID 将目标缓存行逐出缓存
      • Reload：立即读取该缓存行，测量访问时间
      • 若时间差 > 阈值（如 500 cycles），说明 TDX 模块用 TD 的 KeyID 访问过该缓存行
    • 理论依据：MKTME 加密使不同 KeyID 的缓存标签不同，访问后必须清除旧条目
  4. 指令计数推断
    • 时间差分析
      • 每次预防模式执行 1 条指令，触发两次 TDVPS 访问（进入和退出）
      • 公式：指令数 = 缓存未命中次数 / 2
    • 预防模式下，TDX 模块强制 TD 单步执行，访问 TDVPS 的频率与指令数成正比
  5. 控制流关联
    • 页错误触发点
      • 临时阻止 TD 访问特定内存页，迫使 TD 在访问该页时触发页错误，中断预防模式循环
      • 页错误优先级高于预防模式，强制控制权转移

利用 TDX 单步执行预防模式的固有缓存侧信道，通过 KeyID - based Flush + Reload 机制监测 TDVPS 页面的访问次数，推断 TD 执行的指令数。攻击者故意触发预防模式，在单独核心上并行运行侧信道攻击，结合页错误信息揭示 TD 的控制流

改进建议

防御单步攻击

  • 检测优化：原检测机制依赖时间差（4096 rdtsc），攻击者可通过降频绕过
    • 仅依赖指令计数器，设置 “至少执行两条指令” 阈值
    • 公式：若 RIP 增量 < 2× 最长指令长度（15 bytes），触发预防模式
  • 预取机制
    • 在 TDX 模块中预取首条指令，消除人工延迟（参考 AEX-Notify 技术）

防御 StumbleStepping

  • 预防模式：当前预防模式每次执行 1 条指令，导致 TDVPS 访问次数过多，形成侧信道
    • 批量执行随机指令（1-32 条），减少 TDVPS 访问次数
    • 公式：每次执行 PmSteps 指令，仅访问 TDVPS 1 次（进入时）
  • 缓存隔离
    • 为 TDVPS 分配专用缓存区域，物理隔离消除侧信道

wolfssl和openssl：wolfSSL 和 OpenSSL 的非 ce 生成使用截断法，导致控制流泄漏

  • 拒绝采样：生成随机数直到 k < n，而非截断
