自动化测试+硬件漏洞的论文：

MorFuzz: Fuzzing Processor via Runtime Instruction Morphing USENIX Security 2023

  • 创新点：
    1. 动态指令流突变——基于运行时语义，对指令流进行多级“morphing”，有效生成既符合语法又具攻击潜力的测试序列；
    2. 同步‑协同仿真比对——在多种 ISA (Rocket, BOOM, CVA6) 中进行状态同步，抑制模型差异误报。
  • 问题导向：面对 state explosion（状态爆炸）困难，通过智能生成与同步验证缓解模糊器对复杂微体系结构路径的覆盖难题；结果：发现 17 个新 bug，包括 13 个 CVE

HyPFuzz: Formal‑Assisted Processor Fuzzing arXiv / IEEE 2023

  • 创新点：
    1. 混合形式验证驱动——首先由 fuzzer 识别“难到达”设计空间，再借助形式工具精确触发；
    2. 调度优化策略——平衡模糊与形式验证资源分配，有效提升效率（11.7 倍加速）；
  • 问题导向：传统硬件fuzz对控制／数据流深层逻辑覆盖不足，无法触达漏洞；HyPFuzz 结合形式分析突破盲区，成功发现3个前人遗漏的 CVE

DejaVuzz: Dynamic Memory + Differential Taint‑guided Transient‑Bug Fuzzer ArXiv 2025 (USENIX可能接收)

  • 创新点：
  1. 动态可交换内存（dynamic swappable memory）允许同时模拟多个训练场景，提高 transient execution 漏洞触达率；
  2. 差分信息流追踪（differential taint tracking）与 “taint coverage matrix” 引导测试聚焦可泄露态，降低误报；
  • 问题导向：传统transient 漏洞fuzz覆盖不足且误报严重，通过结构设计提升覆盖与效能（4.7×提升）、减少误导，发现5个新CVE

BETA: Automated Black‑box Exploration for Timing Attacks ArXiv 2024

创新点：

  • 定向变异策略——结合 opcode、数据、地址、执行级别多个维度进行智能测试；
  • 指令覆盖反馈机制——依据指令分类反馈剔除低效测试，提升 fuzz 效率；

问题导向：以前黑盒侧信道测试覆盖差、效率低；BETA 在四款 Intel/AMD CPU 上检测出所有已知漏洞，并新增8个 timing 漏洞，实现至少3×的速度提升

延申点：

  1. 指令组合结构化生成：将 MorFuzz 类型的语义变异与 BETA 的反馈机制融合，可实现跨架构的微架构 fuzzing。
  2. 形式验证 + taint：结合 HyPFuzz 的 SMT 驱动与 DejaVuzz 的差分 taint，可用于高效发现 transient 漏洞的同时提供更强准确性。
  3. 通用 vs 专属模糊策略：探索如何利用黑盒反馈机制（如BETA）构造硬件无关的时序/侧道模糊器，覆盖 Arm/AArch、RISC-V等多 ISA 平台。

自动化测试

自动化测试 = 让计算机“自动”执行大量的输入测试操作，以找出潜在的漏洞或异常行为

在硬件安全（尤其是处理器安全）中，自动化测试主要是：

  • 自动构造可疑输入（如汇编指令、系统调用序列）
  • 自动执行这些输入（用模拟器、真实机）
  • 自动分析输出或状态差异，判断是否存在漏洞触发

模糊测试

概念

模糊测试（Fuzzing）是一种最常用的自动化测试方法，它的核心思想就是：

不断输入大量略微变异的、半合法的输入，观察目标程序（或硬件）是否出现异常（如崩溃、输出错乱、状态泄露）。

模糊测试尤其适合：

  • 黑盒测试（不知道内部细节）；
  • 找零日漏洞（0-day）；
  • 覆盖那些“人类不容易想到的奇葩状态”

重点

组成部分 作用 类比说明
种子（Seed） 初始输入样本，用作变异起点 “原始问题模板”
变异器（Mutator） 修改种子的方式（如bit翻转、指令替换） “问题生成器”
执行器（Executor） 将测试输入喂给目标系统并执行 “交卷子给处理器判”
反馈机制（Feedback） 判断是否触发了新状态或异常 “系统给你打分：好问题、坏问题”

种子？fuzz的的起点。原始输入的数据，用于生成更多的变异样本

好的种子能更快进入“关键路径”；

质量差的种子会卡死在无效状态、浪费时间；

种子设计 = 提升效率 + 提高覆盖率 + 增加漏洞触发概率。

graph LR
A[初始种子Seed] --> B[变异器：随机翻转/替换]
B --> C[生成新的测试输入]
C --> D[执行器：QEMU、真实机运行]
D --> E[反馈机制：状态差异/PMU/timing]
E -->|有新状态| A
E -->|无意义| B

这就是“模糊测试引擎”的运行机制，它是一个自动、闭环、演化的过程

测试类型 特点 示例
黑盒 Fuzz 只关注输入和输出，不看内部结构 AFL、Radamsa
灰盒 Fuzz 利用一部分反馈信息（如路径） AFL++ with QEMU
白盒 Fuzz 用符号执行分析路径（需要源码或中间码） KLEE、HyPFuzz
结构感知 Fuzz 利用输入的语义结构，如指令模板 MorFuzz
